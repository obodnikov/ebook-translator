## 1. Задача и объём

Две связанные вещи, и **порядок между ними обязателен**.

**Фильтр значимости.** В запрос каждой стадии кладётся весь глоссарий серии — 95 статей
на 14 433 знака. К отдельному фрагменту относятся 5–7 статей. Остальные 90 не нужны и
вредны дважды: они разбавляют то, что нужно, и составляют больше половины платного входа.

**Проверка единообразия.** Прежде чем менять то, что отвечает за единообразие имён по
серии, нужен способ увидеть, не стало ли хуже. Оценщик для этого не годится — он
расходится сам с собой на 0,68 балла (§2.2). Нужна детерминированная проверка по тексту,
без модели.

**Проверка пишется первой и служит трижды:** как точка отсчёта до фильтра, как приёмочный
критерий после, и как постоянный сторож в дальнейшем.

### Принятые решения

| Вопрос | Решение | Основание |
| --- | --- | --- |
| Что раньше | **Сначала проверка, потом фильтр.** Фильтр не вливается, пока нет замера «до». | Дважды за прошлую сессию шум оценщика был принят за сигнал (§2.2). Менять то, что не умеешь мерить, — тот же путь. |
| По чему отбирать | По **английскому оригиналу** статьи в исходном тексте фрагмента, не по переводу. | Для `translate` перевода ещё не существует. У английского почти нет словоизменения, значит совпадение надёжнее. |
| Словоизменение | Допуск `s`, `es`, `'s`, `’s`; притяжательное окончание снимается с самого термина глоссария. | Замерено: без допуска теряется 48 статей (`Bioform` не находится в `Bioforms`), с допуском — 20. |
| Область поиска | Основные абзацы фрагмента **плюс перекрытие** (`prev`/`next`). | Перекрытие уходит в запрос как контекст, значит термины из него тоже могут понадобиться. |
| Промахи фильтра | Статья, не найденная в оригинале, **просто не попадает** в запрос. Никакого запасного «добавить на всякий случай». | Смысл изменения — убрать лишнее. Полумера сохранит разбавление и не даст замерить эффект. |
| Что делает проверка при расхождении | **Сообщает, не чинит.** | Русское словоизменение неоднозначно; автоправка внесёт свои ошибки. Ср. `repair`, где чинит только привратник с оригиналом на руках. |
| Где живёт отбор | Чистая функция в `series.py`, вызывается на стороне вызывающего кода, а не внутри стадий. | Стадии получают уже готовый блок; их конструкторы не меняются (см. §5.1). |
| Порог приёмки | Единообразие **не ухудшилось**, платный вход **упал не меньше чем на 40%**. | Первое — обязательное условие, второе — ради чего затевается. |

**Не входит в объём.** Перевод текста сносок; фильтрация по типам статей; изменение формата
глоссария; автоматическая правка согласования; выбор статей моделью.

## 2. Что уже измерено

Все числа — прогон «Bear Head», 122 фрагмента, глоссарий серии `dogs-of-war` (95 статей).

### 2.1 Разбавление

| | |
| --- | --- |
| статей в глоссарии | 95 |
| размер блока в запросе | 14 433 знака ≈ 4 800 токенов |
| статей, относящихся к фрагменту | медиана **5** (отбор по переводу), **7** (по оригиналу с допуском окончаний) |
| размер блока после отбора | медиана **1 020 знаков — 7% прежнего** |

### 2.2 Почему нельзя мерить оценщиком

Из [§5.8-в предыдущего документа](2026-08-03-judge-repair-stage-and-reasoning-on-gateway.md):
оценщик, дважды прогнанный по одному и тому же тексту, совпал сам с собой на 18 чанках из
40, средний сдвиг 0,68 балла, дословно повторились 10 замечаний из 68. Замечаний категории
`glossary` во всём прогоне было 12 — на таком количестве при таком разбросе разница не
видна вовсе.

### 2.3 Цена разбавления

Учёт токенов достоверен только для стадий на OpenRouter: шлюз возвращает недостоверные
числа (у `translate` глоссарий выходит 1604% от учтённого входа, чего быть не может).

| стадия | вызовов | вход | из них глоссарий |
| --- | ---: | ---: | ---: |
| `judge` | 393 | 3 693 807 | **51%** |
| `proofread` | 122 | 924 389 | **63%** |

Итого по платным стадиям: 4 618 196 токенов входа, из них глоссарий ≈ 2 477 665 (**54%**).
После фильтрации осталось бы ≈ 124 000.

### 2.4 Дефект, с которого началось

При вычитке найдено «Рой сам придумал», «Рой всё подготовил», «если бы Рой пытался» —
мужское согласование при статье `Bees | Рой | person, f`. По книге: **3 мужских
согласования против 46 верных** (6%; до правки §2.4(а) предыдущего документа было 8 из 48,
то есть 17%).

Прослежено по стадиям: дефект внесён **самим переводом** и прошёл нетронутым через
корректуру, стилистику и сверку. Проводка исправна — в запросе корректора статья стояла
дословно, вместе с примечанием «Referred to with feminine pronouns». Модель имела всё
нужное и не воспользовалась.

> **Осторожно:** связь «разбавление → пропущенный род» **правдоподобна, но не доказана**.
> Фильтр не следует продавать как лечение этого дефекта. Если цель именно род — прямее
> бьёт проверка согласования (§7), она эти три случая ловит наверняка.

## 3. Где сейчас строится блок глоссария

Один и тот же приём повторён в пяти модулях: конструктор стадии получает
`glossary: SeriesGlossary | None` и один раз собирает строку на весь прогон.

| модуль | строка |
| --- | --- |
| [translator.py:89](../../src/booktranslator/translator.py) | `self._glossary_block = render_for_prompt(glossary) if glossary else "(no glossary provided)"` |
| [judge.py:87](../../src/booktranslator/judge.py) | то же |
| [reflect.py:84](../../src/booktranslator/reflect.py) | то же |
| [postprocess.py:139](../../src/booktranslator/postprocess.py) | то же |
| [repair.py:266](../../src/booktranslator/repair.py) | то же |

Подставляется в контекст под именем `glossary_block`
([translator.py:111](../../src/booktranslator/translator.py),
[judge.py:100](../../src/booktranslator/judge.py),
[reflect.py:99,119](../../src/booktranslator/reflect.py),
[postprocess.py:158](../../src/booktranslator/postprocess.py),
[repair.py:330](../../src/booktranslator/repair.py)) и используется во всех семи промптах.

Сама отрисовка — [series.py:168 `render_for_prompt`](../../src/booktranslator/series.py):
по строке на статью, `original | translation | type[, gender] | notes`, примечание
обрезается до 120 знаков.

**Ключевое следствие для объёма работ:** блок собирается **один раз на стадию**, а нужен
**свой на каждый фрагмент**. Это и есть главное изменение (§5.1).

## 4. Фаза 1 — проверка единообразия (пишется первой)

Новый модуль `src/booktranslator/glossary_check.py`, без обращений к модели.

### 4.1 Что проверяется

Три независимых правила. Каждое даёт список находок с номером фрагмента и абзаца.

**(а) Термин переведён не канонически.** Английский термин статьи есть в исходном
фрагменте, а канонического перевода в переведённом абзаце нет.

Осторожно с ложными срабатываниями: русское словоизменение. Сравнивать надо по **основе**,
а не по точной строке. Практичный приём без морфологического разбора: отбросить у
канонического перевода последние 1–3 буквы и искать основу. Длину отсечения подобрать по
замеру на этой книге; если ложных срабатываний слишком много — сузить правило до статей
типа `person` и `place`, где перевод обычно имя собственное.

**(б) Согласование по роду.** Для статей с `gender` в (`m`, `f`, `n`): найти в переводе имя
и следующее за ним слово с окончанием прошедшего времени (`-л`, `-ла`, `-ло`) в пределах
трёх слов, сверить окончание с объявленным родом.

Порог осторожности: считать находкой только глагол **непосредственно после** имени или
через служебные слова (`же`, `уже`, `не`, `бы`, `тоже`, `всё`, `ведь`). Замерено: широкий
шаблон «в пределах трёх слов» дал одно ложное срабатывание из четырёх — в «Рой торопилась,
догадался Аслан» глагол относится к другому подлежащему.

**(в) Разнобой между фрагментами.** Один и тот же английский термин переведён в разных
фрагментах по-разному. Это единственное правило, которое видит книгу целиком, и оно ближе
всего к тому, ради чего глоссарий существует.

### 4.2 Команда

```
btrans check-glossary <epub> [--series SLUG | --glossary PATH] [--work DIR]
                             [--from STAGE] [--json PATH]
```

- `--from` — какую стадию проверять; по умолчанию текст, из которого собралась бы книга
  (тот же смысл, что у `btrans judge --from final`).
- `--json` — выгрузка находок для сравнения «до/после»; без неё печатается сводка.

Обращений к модели нет, стоимость нулевая, время — секунды.

### 4.3 Формат находки

```python
@dataclass(frozen=True)
class Finding:
    rule: Literal["not_canonical", "gender", "inconsistent"]
    chunk_id: str
    paragraph: int | None      # 1-based, если удалось определить
    term: str                  # английский термин статьи
    expected: str              # канонический перевод или ожидаемый род
    found: str                 # что стоит в тексте
    excerpt: str               # ±60 знаков вокруг, для глаза
```

Сводка печатает счётчики по правилам и по статьям, полный список — в `--json`.

### 4.4 Приёмка фазы 1

- Проверка находит все три известных случая рода в `ch25_c01` (правило «б»).
- Не срабатывает на «Рой торопилась, догадался Аслан» (известное ложное срабатывание).
- Доля ложных срабатываний по правилу «а» проверена вручную на выборке 30 находок и
  задокументирована числом в этом файле.

## 5. Фаза 2 — фильтр значимости

### 5.1 Отбор

В `series.py`:

```python
def entries_for_text(glossary: SeriesGlossary, source_text: str) -> list[SeriesGlossaryEntry]
def render_for_prompt_filtered(glossary: SeriesGlossary, source_text: str) -> str
```

Правило совпадения (замерено в §2.1):

```python
core = re.sub(r"['’]s$", "", entry.original)
pattern = re.compile(r"\b" + re.escape(core) + r"(?:['’]s|es|s)?\b", re.IGNORECASE)
```

Шаблоны собираются один раз на глоссарий и переиспользуются — иначе 95 компиляций на
фрагмент.

Порядок статей сохраняется как в глоссарии; пустой отбор даёт `(no relevant terms)`.

### 5.2 Как блок доезжает до стадии

Сейчас блок собирается в конструкторе, а нужен на каждый фрагмент. Наименее навязчивый
способ, не ломающий существующие вызовы:

- конструктор каждой стадии дополнительно принимает
  `glossary_source: Callable[[str], str] | None = None` — функцию «по идентификатору
  фрагмента вернуть блок»;
- если она не передана, поведение прежнее: общий `self._glossary_block`;
- `_build_context` берёт `glossary_source(chunk_id)`, когда она есть.

Вызывающий код (`cli.py`) строит замыкание поверх `ChunkSet`: по `chunk_id` собрать
исходный текст через `render_main` + `render_overlap` и отдать отфильтрованный блок. Блоки
кэшируются по `chunk_id` в словаре — фрагментов сотни, а стадий пять.

> **Важно:** исходный текст берётся из **нетронутого** `ChunkSet`. После перевода
> `chunk_set` содержит перевод, а не оригинал
> ([translator.py:271-277](../../src/booktranslator/translator.py)) — это та самая
> неисправность, из-за которой оценщик сравнивал перевод сам с собой. В `cli.translate`
> для этого уже есть `source_chunk_set`; фильтр обязан пользоваться им.

### 5.3 Влияние на кэш

Блок глоссария входит в запрос, а запрос — в ключ кэша. **Фильтрация обесценивает весь
накопленный кэш всех стадий.** Это не побочный эффект, а неизбежность: запрос действительно
другой.

Из этого следует порядок работ: изменение вливается перед переводом новой книги, а не
посреди работы над имеющейся.

### 5.4 Приёмка фазы 2

| условие | как проверяется |
| --- | --- |
| единообразие не ухудшилось | `btrans check-glossary --json` до и после, сравнение по числу находок каждого правила |
| платный вход упал ≥ 40% | сумма `input_tokens` по `judge` и `proofread` за сопоставимый прогон |
| отбор не теряет нужного | доля статей, найденных в переводе, но не отобранных по оригиналу — не хуже замеренных 20 из 122 фрагментов |
| ничего не сломано | набор тестов зелёный, `ruff` чист |

## 6. Порядок работ

1. `glossary_check.py` + команда `btrans check-glossary` + тесты. **Ничего больше не
   трогать.**
2. Прогнать по «Bear Head», сохранить `--json` как точку отсчёта. Проверить долю ложных
   срабатываний вручную, число записать в §4.4.
3. `entries_for_text` / `render_for_prompt_filtered` + тесты. Пока никуда не подключать.
4. Подключить к стадиям через `glossary_source`, по одной стадии за коммит.
5. Перевести книгу заново на отфильтрованном глоссарии.
6. Прогнать проверку и сравнить с точкой отсчёта. Свести расход по платным стадиям.
7. Решение по §5.4: вливать или откатывать.

Шаги 1–4 бесплатны. Платный только шаг 5 (оценка и корректура) и он же единственный
настоящий приёмочный прогон.

## 7. Смежное: проверка согласования как отдельная стадия

Правило «б» из §4.1 может остаться диагностикой, а может стать сторожем в конвейере — по
образцу защиты тире прямой речи
([postprocess.py `_breaks_dialogue_dash`](../../src/booktranslator/postprocess.py)): правка,
ломающая согласование с объявленным родом, отклоняется, абзац остаётся прежним.

**Решение отложено** до появления числа ложных срабатываний из шага 2. Отклонять правки по
шаблону, ошибающемуся в четверти случаев, — верный способ навредить.

## 8. Риски

| риск | вероятность | что делаем |
| --- | --- | --- |
| Фильтр теряет нужную статью, единообразие падает | средняя | Приёмка §5.4 это ловит: проверка написана раньше фильтра именно для этого. |
| Проверка единообразия шумит ложными срабатываниями и обесценивается | высокая для правила «а» | Правило сужается до `person`/`place`, где перевод — имя собственное. Число ложных срабатываний замеряется вручную на шаге 2, а не предполагается. |
| Обесценивание кэша застаёт врасплох посреди работы | низкая | §5.3: вливать перед новой книгой. |
| Экономия окажется меньше обещанной | низкая | 54% платного входа замерены, не прикинуты. Даже половина этого окупает работу. |
| Фильтр не починит род, и это сочтут провалом | средняя | §2.4 говорит об этом заранее: связь не доказана, цель фильтра — расход и порядок. |

## 9. Открытые вопросы

1. **Длина отсечения основы** в правиле «а» — 1, 2 или 3 буквы. Решается замером на шаге 2,
   не рассуждением.
2. **Нужны ли статьи из перекрытия.** Сейчас решено брать (§1), но если отбор окажется
   шире нужного — проверить, много ли даёт перекрытие отдельно.
3. **Что делать с 20 промахами** отбора по оригиналу. Возможно, это статьи, которые
   переводчик применил по смыслу, а не по букве, и в запросе они действительно не нужны.
   Проверяется глазами на выборке.
4. **Стоит ли фильтровать для `judge`.** Оценщик ищет несоответствия глоссарию — ему,
   возможно, нужен более широкий список, чем стадии перевода. Замерить отдельно: доля
   замечаний категории `glossary` до и после.
